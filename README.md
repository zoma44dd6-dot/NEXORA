# نبض | NABD Health Platform

منصة عربية RTL للمعلومات الطبية ودليل أولي للأمراض والأمراض النادرة والأدوية والمستشفيات. يتضمن المشروع واجهة متجاوبة، بحثًا محليًا، API باستخدام Express، ملف بيانات JSON، وتسجيل دخول للوحة الإدارة لإضافة مدخلات أساسية.

> **تنبيه مهم:** هذا مشروع تقني أولي قابل للتشغيل، وليس موسوعة طبية مكتملة أو نظامًا طبيًا معتمدًا. البيانات الموجودة أمثلة محدودة فقط. يجب أن يراجع مختصون كل محتوى طبي قبل نشره للمرضى، وأن تتحقق الجهة المالكة من بيانات المستشفيات والخدمات والأدوية. لا تستخدم المنصة للتشخيص أو لاتخاذ قرارات علاجية.

## المتطلبات
- Node.js 20 أو أحدث
- اتصال بالإنترنت عند تثبيت Express (الخطوط الخارجية اختيارية)

## التشغيل محليًا
1. فك ضغط الملف.
2. افتح الطرفية داخل مجلد `nabd`.
3. نفّذ:
   ```bash
   npm install
   ```
4. انسخ `.env.example` إلى `.env` وعدّل كلمة مرور الإدارة والمفتاح السري.
5. شغّل التطبيق:
   ```bash
   npm start
   ```
6. افتح `http://localhost:3000`.

### بيانات الإدارة
الإعدادات الافتراضية للتطوير موجودة في `.env.example`. غيّر كلمة المرور و`SESSION_SECRET` قبل أي نشر، ولا ترفع ملف `.env` إلى GitHub. لا تستخدم بيانات الدخول الافتراضية على خادم عام.

## النشر
GitHub يخزن الكود، لكنه لا يشغّل خادم Express وحده عبر GitHub Pages. انشر التطبيق على خدمة تدعم Node.js (مثل Render أو Railway أو VPS)، واضبط متغيرات البيئة `ADMIN_EMAIL` و`ADMIN_PASSWORD` و`SESSION_SECRET` و`NODE_ENV=production`.

**البيانات:** يخزن الخادم البيانات في `data/db.json` وينشئه تلقائيًا من `data/seed.json` عند أول تشغيل. نظام JSON مناسب للديمو أو بداية صغيرة فقط؛ قبل الاستخدام العام، انقل البيانات إلى PostgreSQL أو قاعدة بيانات مُدارة مع نسخ احتياطي وصلاحيات مناسبة. بعض منصات الاستضافة تستخدم قرصًا مؤقتًا ما لم تُضف تخزينًا دائمًا.

## وظائف متوفرة
- واجهة عربية متجاوبة، أقسام الأمراض والأمراض النادرة والأدوية والمستشفيات.
- البحث داخل المدخلات المحملة، وفلاتر التصنيف.
- صفحات تفاصيل للأمراض والأدوية مع مراجع عندما تكون موجودة.
- API: `GET /api/health`, `GET /api/summary`, `GET /api/diseases`, `GET /api/medications`, `GET /api/hospitals`.
- دخول إدارة وإضافة مدخلات عبر الواجهة.
- واجهات API لتعديل وحذف العناصر محمية برمز الإدارة.

## قبل الإطلاق الحقيقي
- إضافة قاعدة بيانات إنتاجية وترحيلات ومراقبة وأخطاء منظمة.
- استخدام مزود هوية موثوق، تحديد معدل محاولات الدخول، وإضافة حماية CSRF حسب نمط النشر، وسياسة تدوير الجلسات.
- مراجعة أمنية مستقلة؛ إعداد HTTPS والنسخ الاحتياطي والاستعادة.
- مراجعة قانونية وخصوصية متوافقة مع قوانين حماية البيانات المعمول بها، خصوصًا إذا جُمعت بيانات صحية أو تقارير مرضى.
- نظام تحرير ومراجعة طبية بمراحل اعتماد، ومصادر وتواريخ مراجعة واضحة.
- التحقق المباشر من المستشفيات والأطباء والأدوية والخدمات والتكاليف قبل عرضها باعتبارها متاحة.
- إضافة اختبارات آلية وCI قبل الإطلاق.
